# Misogyny in Spanish song lyrics — dataset & evaluation

Code and data for a paper on detecting misogynistic content in Spanish song
lyrics: a human-annotated corpus of songs labelled `M` / `NM` (plus misogyny
subtypes), analysis notebooks over the annotations and their metadata, and a
zero-shot LLM evaluation harness.

Python 3.12, managed with [uv](https://docs.astral.sh/uv/). **All commands are run
from the repository root.**

```bash
uv sync
```

## Layout

```
data/          corpus, annotations and metadata (see "Data" below)
notebooks/     analysis, numbered in pipeline order
scripts/       command-line entry points
prompts/       LLM prompt templates
predictions/   model output, one CSV per (model, temperature)
slurm/         cluster job scripts for the evaluation sweep
```

## Pipeline

| Stage | What runs | Produces |
|---|---|---|
| 1. Corpus & annotations | *(external — not produced in this repo)* | `train.csv`, `test.csv`, `wide.csv`, `dataset_sin_pseudoetiquetado.csv`, `songs_metadata.csv` |
| 2. Slim the metadata | `scripts/build_clean_metadata.py` | `data/songs_metadata_clean.csv` |
| 3. Explore | `notebooks/01`–`05` | figures; `annotation_time_splits.csv` |
| 4. LLM inference | `scripts/evaluate.py` (via `slurm/`) | `predictions/<model>_<temperature>.csv` |
| 5. Ensemble & score | `scripts/majority_vote.py` | `predictions/<model>_vote<n>_k<k>.csv` |

### Notebooks

Run in order; each is self-contained and reads from `data/`.

| Notebook | Purpose |
|---|---|
| `01_song_selector.ipynb` | Interactive browser (label × country) for picking prompt-design examples. |
| `02_data_analysis.ipynb` | Label distribution by split and country, subtype and stereotype rates, lyrics length. |
| `03_songs_metadata_eda.ipynb` | 14-section audit of the 84-column metadata: enrichment coverage, genres, artist demographics, misogyny over time, train/test integrity. |
| `04_verse_statistics.ipynb` | Verses per song and verse length; cross-validates `wide.csv` against the annotation export. |
| `05_annotation_time_splits.ipynb` | Builds three disjoint, stratified ~10% splits for timing annotation work. |

Notebooks resolve `data/` with `DATA = Path("../data") if Path("../data").exists()
else Path("data")`, so they run both from `notebooks/` and from the repo root.
Keep that idiom when adding new ones.

### Scripts

```bash
# Slim the 84-column metadata down to 20 analysis-ready columns
uv run python scripts/build_clean_metadata.py

# Zero-shot inference over the test split (needs a GPU)
uv run python scripts/evaluate.py --model_name Qwen/Qwen3-8B --temperature 0.7

# Majority-vote ensemble over every temperature found on disk, with metrics
uv run python scripts/majority_vote.py --model_name Qwen/Qwen3-8B
```

`evaluate.py` writes `predictions/{model_with_slashes_as_underscores}_{temperature}.csv`;
`majority_vote.py` globs those back in, prints per-run and per-threshold scores
(accuracy, per-class P/R/F1, macro-F1, confusion counts) and writes the vote table.
Pass `--help` to either for the full options.

Two auxiliary lookup scripts, neither wired into the pipeline above, need API
credentials:

```bash
export LASTFM_API_KEY=...   # https://www.last.fm/api/account/create
uv run python scripts/fetch_lastfm_songs.py --tag hip-hop --limit 50 --out data/lastfm_tracks.csv

export MB_CONTACT="you@example.com"   # MusicBrainz requires contact info in the User-Agent
uv run python scripts/fetch_musicbrainz_info.py --artist "Daft Punk" --title "One More Time"
```

### Cluster sweep

```bash
bash slurm/submit_temperature_sweep.sh   # from the login node, not as a job
```

Submits one `slurm/run_evaluation.sbatch` job per temperature
(`0.0 0.3 0.7 1.0 1.3`), each chained to the previous with `--dependency=afterany`
so only one GPU job is active at a time. Model and temperature arrive via
`sbatch --export`; logs land in `logs/`.

## Data

| File | Grain | Notes |
|---|---|---|
| `train.csv` | one row per song (2,303) | `lyrics`, `language`, misogyny label + subtypes |
| `test.csv` | one row per song (576) | same schema; held out |
| `wide.csv` | one row per verse (23,890) | per-annotator labels pivoted into columns, **no verse text** |
| `dataset_sin_pseudoetiquetado.csv` | one row per *annotation* (~642k) | the only file carrying verse text; each verse repeats once per annotator |
| `songs_metadata.csv` | one row per song | 84 columns: raw Genius/Last.fm/MusicBrainz/Wikidata/AcousticBrainz fields mixed with resolved ones |
| `songs_metadata_clean.csv` | one row per song (2,875) | generated — 20 resolved columns, see the script docstring |
| `annotation_time_splits.csv` | one row per verse (6,621 over 870 songs) | generated by notebook `05` |
| `genre_main_review.xlsx`, `genre_main_value_counts.txt` | — | manual genre review aids |
| `songs_to_remove.txt` | 8 song ids | exclusion list; not referenced by any code |

Provenance: only `songs_metadata_clean.csv` and `annotation_time_splits.csv` are
produced in this repo. The corpus files come from an upstream annotation pipeline
that lives elsewhere.

> **Known defect.** The metadata was linked to `test.csv` by *fuzzy title matching*
> (`test_id` = the 1-based row number of `test.csv`, plus `test_match_score`), not
> by `song_id`. The `in_train` / `in_test` flags therefore disagree with real split
> membership, and 4 of the 576 test songs have no metadata row at all. See
> `03_songs_metadata_eda.ipynb` §12.2 before relying on those flags.

## Prompts

`prompts/baseline.md` is a zero-shot chain-of-thought template with
`{song_lyrics_title}` and `{lyrics}` placeholders. It must end with this exact
output contract, which `evaluate.py` parses by regex:

```
Reasoning: <2-4 sentences>
Misogyny: <NM or M>
```

A prompt that breaks the contract yields empty predictions rather than an error, so
check the `is_misogynistic_pred` column is populated after changing it.
